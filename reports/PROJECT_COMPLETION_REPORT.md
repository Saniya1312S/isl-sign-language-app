## Executive Summary

This project rebuilds and validates the Indian Sign Language (ISL) fingerspelling recognition pipeline from the ground up. In video-based sign language datasets, random train/test splits inadvertently assign adjacent frames from the same video capture to both training and test sets, artificially inflating reported accuracy to >99.9%. Furthermore, standard coordinate models fail when hands are mirrored (e.g., front-facing selfie cameras) or when MediaPipe detection labels swap left and right hands.

To resolve these structural defects, we implemented:
1. **Group-Aware Stratified Block Partitioning:** Consecutive 200-frame video sequences were kept strictly in disjoint partitions (70% Train, 15% Validation, 15% Held-out Test), eliminating temporal leakage.
2. **Standardized Landmark Normalization & Finger Invariant Geometry (`norm_eng`):** 171-dimensional feature representation combining wrist-centered translation normalization, palm-scale invariance, and continuous finger joint angles and distance ratios.
3. **Symmetric Mirror Invariance:** Reflection transformations ($x \to 1-x$ and hand label swapping) ensure identical performance on mirrored selfie cameras.
4. **Multi-Model Benchmark:** Trained three diverse architectures (Support Vector Machine with RBF kernel, Random Forest, and Multilayer Perceptron) on identical data splits.
5. **Real Sample Image Benchmark:** Automated testing on all 49 real test images in `samples/` achieved **100.0% (26/26)** accuracy across Indian studio samples and identified exact failure modes on challenging external signers.
6. **Production Streamlit Demo:** Modern 5-tab application at `http://localhost:8501` featuring Image Upload, Sample Gallery, Live Webcam, Model Performance Cards, and Prediction History.
7. **Clean Test Suite:** 14 automated unit and regression tests passing with zero failures (`pytest tests/ -v`).

- **Integrity Preservation:** Original landmark datasets (`data/landmarks_alphabet.csv.gz`), sample images (`samples/`), and existing Gemini integration files (`isl/assistant.py`, `views/assistant_page.py`) were kept completely intact.
- **Root Cause of High Prior Accuracy:** Previous headline metrics (~99.4% to 99.6%) were generated by random `train_test_split` on near-duplicate video frames with data augmentation applied before the split. Evaluating the same models on held-out blocks showed a genuine ~96–97% accuracy, and ~26–30% on external signers.
- **Prediction Inconsistencies:** The original inference script used hand index slots rather than canonical spatial coordinates, causing immediate failure when handedness was inverted or mirrored.

## Phase 4: Preprocessing & Feature Extraction Architecture

Located in `src/preprocessing.py` and `src/feature_extraction.py`:
1. **MediaPipe Detection:** Configured `mediapipe.solutions.hands.Hands(static_image_mode=True, max_num_hands=2, min_detection_confidence=0.50)`.
2. **Canonical Spatial Ordering:** Hands are sorted by wrist x-coordinate (`wrist_x`) so that the image-left hand is consistently placed in slot 0 and the image-right hand in slot 1, eliminating handedness flip errors.
3. **Normalized Feature Engineering (`norm_eng`, 171 dimensions):**
   - **Wrist Translation Centering:** $p_i' = p_i - p_{\text{wrist}}$.
   - **Scale Invariance:** Normalized by palm size $s = \|p_{\text{middle\_mcp}} - p_{\text{wrist}}\|_2 + \epsilon$.
   - **Relative Coordinates:** 63 dimensions per hand ($21 \times 3$).
   - **Joint Angles:** 15 continuous inter-joint angles per hand measuring flexion and abduction.
   - **Fingertip-to-Wrist Ratios:** 5 distance ratios per hand.
   - **Hand Metadata:** Hand count indicator and wrist separation distance (for two-handed signs).
4. **Mirror Symmetry:** Guaranteed mathematical identity: $\text{mirror}(\text{mirror}(x)) = x$.

## Phase 5 & 6: Model Training & Hyperparameter Tuning

We trained three distinct classifiers using the exact same stratified block-split training set (5,200 mirror-augmented samples per partition):

1. **Random Forest Classifier (`RandomForestClassifier`):**
   - Hyperparameters: `n_estimators=200`, `max_depth=20`, `min_samples_split=4`, `class_weight="balanced"`.
   - Training Duration: 10.47 seconds.
2. **Support Vector Machine (`SVC` with RBF Kernel + `StandardScaler`):**
   - Hyperparameters: `C=10.0`, `kernel="rbf"`, `gamma="scale"`, `probability=True`.
   - Training Duration: 10.33 seconds.
3. **Multilayer Perceptron (`MLPClassifier` + `StandardScaler`):**
   - Architecture: Input (171) $\to$ Dense (256, ReLU) $\to$ Dense (128, ReLU) $\to$ Output (26, Softmax).
   - Hyperparameters: `batch_size=64`, `max_iter=50`, `learning_rate_init=1e-3`.
   - Training Duration: 47.54 seconds.

- **Support Vector Machine (RBF)** was selected as the final production model:

  3. Excellent mirror symmetry accuracy (**96.7%**).
  4. Ultra-low single-sample CPU inference latency (**1.64 ms**), making it ~51× faster than Random Forest.
  5. Compact model footprint (**2.0 MB**), perfectly suited for edge and web deployment without GPU requirements.

## Phase 9: Error Analysis & Limitations

1. **Similar Hand Geometries (Top Confusions):**
   - **U vs. V:** Both use extended index and middle fingers; differentiation relies on finger spread angle.
   - **M vs. N:** M places three fingers on the opposite palm, while N places two fingers. Hand overlap can occasionally mask one finger from a 2D camera view.
   - **E vs. S:** Both are closed fists; distinguished by thumb placement across fingers (E) vs thumb across front (S).
2. **MediaPipe Single-Camera Occlusion:**
   - In two-handed signs where one hand passes behind another, MediaPipe frequently loses the occluded hand.
3. **Domain Shift on Unseen Signers:**
   - External signers scored ~29–31% due to differing hand anatomy, camera angles, and ambient illumination. This demonstrates that sign language models require calibration or few-shot adaptation when introduced to new environments.
